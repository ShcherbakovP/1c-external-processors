# Обработка «ОчисткаКопииДляDev»

Внешняя обработка на обычной форме. Непосредственно (без пометки на удаление)
чистит служебные и историйные данные из копии рабочей базы перед тем, как
разворачивать из неё dev-базу. Удаляет порциями в отдельных транзакциях,
показывает прогресс и позволяет прервать работу в любой момент.

Работает в двух режимах, выбор задаёт реквизит «Дата отсечки»:

- **дата пустая** — полная очистка отмеченных категорий (исходное поведение);
- **дата задана** — обрезка по периоду: удаляются только записи старше этой даты,
  записи с неё и новее сохраняются. Обрезка применяется к объектам, у которых
  есть реквизит-дата (журнал AEMZ по реквизиту `Период`, справочники истории по
  `Дата`, периодические регистры по `Период`). Объекты без реквизита-даты при
  заданной отсечке пропускаются, чтобы их случайно не снесло целиком. У
  иерархического справочника удаляются только записи-листья, группы остаются.

Тулинг проекта собирает только управляемые формы, а целевая конфигурация —
обычное приложение, поэтому обработку нужно один раз собрать руками в
Конфигураторе. Дальше готовый `.epf` можно переиспользовать на любой копии.

## Сначала прочитайте

- **Полная очистка — только на КОПИИ базы.** Удаление необратимое, минуя пометку
  и контроль ссылочной целостности. Режим полной очистки (дата отсечки пустая) на
  рабочей базе запускать нельзя.
- **Останутся «битые» ссылки (только при полной очистке).** Если на удалённые
  письма, файлы или уведомления ссылались сделки, клиенты и прочие объекты,
  ссылки станут недействительными. Для dev-базы это обычно терпимо, но знать об
  этом нужно.
- **Обрезка по периоду битых ссылок не создаёт.** Журнал AEMZ и справочники
  истории — это накопители аудита, на которые другие объекты не ссылаются.
  Поэтому обрезку этих объектов по дате допустимо выполнять и на рабочей базе, но
  только при свежем бэкапе, в окно низкой нагрузки и по решению ответственного.
  Это не действие «по умолчанию»: восстановить удалённое можно лишь из бэкапа.
- **Журнал изменений объектов огромный.** `ЖурналРегистрацииИзмененияОбъектов_AEMZ`
  — около 24 млн элементов и 90 млн строк табличной части. Объектное удаление
  такого объёма идёт очень долго (часы, а то и десятки часов). Запускайте его
  отдельно и с запасом по времени. Работу можно прервать (Ctrl+Break между
  порциями) и продолжить повторным запуском — обработка добьёт остаток.
- **Регистр Битрикс24 чистится одной операцией.** 6,6 млн записей удаляются
  единой транзакцией, это может занять несколько минут — так и задумано, ждите.

## Шаг 1. Создать внешнюю обработку

1. Конфигуратор → Файл → Новый → **Внешняя обработка**.
2. Имя: `ОчисткаКопииДляDev`. Синоним: «Очистка копии для dev».

## Шаг 2. Добавить реквизиты обработки

В дереве обработки → ветка **Реквизиты** → добавить:

| Имя                  | Тип    | Примечание                              |
|----------------------|--------|-----------------------------------------|
| `ФлЖурналИзменений`  | Булево | Журнал изменений объектов               |
| `ФлИсторияРаботы`    | Булево | История работы и история объектов       |
| `ФлСинхрБитрикс`     | Булево | Идентификаторы синхронизации Битрикс24  |
| `ФлОчередиСинхр`     | Булево | Очереди «нужно синхронизировать»        |
| `ФлЗвонкиЧаты`       | Булево | Журнал звонков, чаты, контакты, лог     |
| `ФлПочта`            | Булево | Почта, письма, вложения                 |
| `ФлУведомленияФайлы` | Булево | Уведомления и присоединённые файлы      |
| `ФлЗадачи`           | Булево | CRM-задачи                              |
| `ДатаОтсечки`        | Дата   | Состав даты — «Дата». Пусто = полная очистка; задано = обрезка |
| `РазмерПорции`       | Число  | Длина 7, без дробной части. По умолч. 5000 |
| `ТекстРезультата`    | Строка | Неограниченной длины (длина 0)          |

## Шаг 3. Создать обычную форму

1. В дереве обработки → ветка **Формы** → добавить форму.
2. Вид формы — **Обычная форма** (не управляемая!). Назначить основной.

Разместите на форме элементы (привязка к реквизитам — через свойство «Данные»):

**Группа флажков** (каждый — Поле флажка, данные = соответствующий реквизит):
- «Журнал изменений объектов (≈24 млн, удаляется долго)» → `ФлЖурналИзменений`
- «История работы и история объектов» → `ФлИсторияРаботы`
- «Синхронизация Битрикс24 (идентификаторы)» → `ФлСинхрБитрикс`
- «Очереди синхронизации» → `ФлОчередиСинхр`
- «Звонки, чаты, контакты с клиентами» → `ФлЗвонкиЧаты`
- «Почта, письма, вложения» → `ФлПочта`
- «Уведомления и файлы» → `ФлУведомленияФайлы`
- «CRM-задачи» → `ФлЗадачи`

**Поле ввода** «Дата отсечки» → данные `ДатаОтсечки`. Оставьте пустым для полной
очистки; задайте дату (например, `01.01.2026`), чтобы удалить только записи
старше неё, сохранив записи с этой даты.

**Поле ввода** «Размер порции» → данные `РазмерПорции`.

**Две кнопки** (обычные кнопки на форме или в командной панели):
- `КнопкаПосчитать`, заголовок «Посчитать». Действие → процедура
  `КнопкаПосчитатьНажатие`.
- `КнопкаВыполнить`, заголовок «Удалить отмеченное». Действие → процедура
  `КнопкаВыполнитьНажатие`.

**Поле лога** — Поле ввода, данные `ТекстРезультата`, свойства:
многострочный режим = Истина, только просмотр = Истина, растянуть по высоте.

> Имена кнопок и процедур должны совпадать буква в букву, иначе действие не
> привяжется. Можно создать команды через контекстное меню кнопки («Действие →
> Создать»), тогда заготовки процедур появятся сами, и в них нужно будет
> вставить вызовы из модуля.

## Шаг 4. Вставить модуль

Открыть **Модуль формы** и вставить целиком содержимое файла `Модуль.bsl`
из этой же папки.

## Шаг 5. Сохранить и запустить

1. Сохранить обработку как `ОчисткаКопииДляDev.epf`.
2. В режиме 1С:Предприятие на **копии**: Файл → Открыть → выбрать `.epf`.
3. Отметить нужные категории, при необходимости поменять размер порции.
   Для обрезки по периоду задать **дату отсечки** (например, `01.01.2026`, чтобы
   оставить только текущий год); для полной очистки оставить дату пустой.
4. Нажать **«Посчитать»** — обработка покажет количество записей по каждому
   объекту и итог, ничего не удаляя. При заданной дате отсечки считаются только
   записи, попадающие под удаление (старше неё). Это безопасная проверка.
5. Нажать **«Удалить отмеченное»** и подтвердить. Ход операции виден в окне
   состояния (полоса прогресса), итоговый лог появится в поле после завершения.

## Как это работает внутри

- **Справочники и документы** удаляются объектно, порциями по `РазмерПорции`:
  выбирается очередная пачка ссылок, каждый объект получается и удаляется
  непосредственно (`Объект.Удалить()`), порция фиксируется своей транзакцией.
  При непосредственном удалении документа `ЭлектронноеПисьмо` его движения по
  регистрам платформа удалит сама.
- **Независимые регистры сведений** при полной очистке чистятся целиком: запись
  пустого набора без отбора удаляет все записи одной операцией. При обрезке по
  периоду регистр целиком не чистится: периодический обрабатывается порциями с
  отбором `Период < ДатаОтсечки`, непериодический пропускается.
- **Обрезка по периоду** добавляет в запрос выборки порции условие
  `<реквизит-дата> < &ДатаОтсечки`. У иерархического справочника (журнал AEMZ)
  добавляется ещё `И НЕ ЭтоГруппа`, поэтому удаляются только записи-листья, а
  группы и иерархия не разрушаются. Удаление одной записи журнала автоматически
  убирает и строки её табличной части `Изменения`.
- Между порциями вызывается `ОбработкаПрерыванияПользователя()`, так что Ctrl+Break
  останавливает работу аккуратно. Ошибка в порции откатывает только эту порцию,
  пишется в лог и в журнал регистрации, после чего объект пропускается.

## Рекомендация по порядку

**Для dev-копии (полная очистка, дата отсечки пустая):**

1. Сначала прогоните всё, кроме журнала изменений — это быстро и снимает
   основной объём по регистрам и истории.
2. Журнал изменений (24 млн) запускайте отдельно, оценив время. Если база
   серверная (SQL) и журнал нужно просто обнулить целиком, очистка таблицы
   средствами СУБД будет на порядки быстрее объектного удаления — но это уже вне
   обработки и требует аккуратности с именами таблиц.

**Для обрезки по периоду (оставить только текущий год):**

1. Задайте дату отсечки `01.01.2026` (начало текущего года).
2. Отметьте «Журнал изменений объектов» и «История работы», нажмите
   **«Посчитать»** — сверьте, сколько записей попадает под удаление.
3. Нажмите **«Удалить отмеченное»**. Объёмы большие (журнал AEMZ — миллионы
   записей старше года), поэтому закладывайте время и при необходимости прерывайте
   и продолжайте повторным запуском. Записи текущего года и группы остаются.
4. Объектное удаление таких объёмов идёт долго. Если приемлемо и есть аккуратный
   доступ к СУБД, тот же отбор по дате можно выполнить как `DELETE` на сервере, но
   тогда придётся вручную перестроить полнотекстовый индекс и почистить историю
   данных — обработка делает это штатно сама.
